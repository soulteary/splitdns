# Contributing to splitdns

Thanks for your interest in contributing! `splitdns` is a small, macOS-only Go
CLI for managing `/etc/resolver` suffix-based Split DNS. This guide explains how
to set up your environment, run the checks, and open a good pull request.

## Development setup

- **macOS** (Apple Silicon or Intel). The tool and its integration tests are
  macOS-only.
- **Go 1.26+** (see [`go.mod`](./go.mod); module path is
  `github.com/soulteary/splitdns`).
- Optional: [`golangci-lint`](https://golangci-lint.run/) for `make lint`.

Clone and build:

```bash
git clone https://github.com/soulteary/splitdns.git
cd splitdns
make build      # produces ./splitdns
```

## Make targets

These targets exist in the [`Makefile`](./Makefile):

| Target | What it does |
| --- | --- |
| `make fmt-check` | Verify formatting with `gofmt` (fails if any file needs formatting) |
| `make vet` | Run `go vet ./...` |
| `make test` | Run unit tests (`go test ./...`) |
| `make lint` | Run `golangci-lint run` |
| `make build` | Build the `./splitdns` binary |
| `make integration` | Run read-only integration tests (`go test -tags integration ./...`) |

`make fmt` (without `-check`) rewrites files in place with `gofmt -w .`.

Before opening a PR, run at least:

```bash
make fmt-check vet test
```

## Tests

- **Unit tests are hermetic.** All filesystem access uses temp directories and
  all external commands go through an injectable fake runner. They do not touch
  `/etc/resolver` and do not run real system commands, so they are safe to run
  anywhere Go is available.
- **Integration tests are read-only and macOS-only.** They use the
  `//go:build integration` build tag and only *observe* real DNS state; they
  never modify `/etc/resolver`. Run them with `make integration`.

## Commit style

Please use [Conventional Commits](https://www.conventionalcommits.org/)-style
prefixes (`feat:`, `fix:`, `docs:`, `test:`, `chore:`, `refactor:`, etc.).

The release changelog is generated by GoReleaser (see
[`.goreleaser.yaml`](./.goreleaser.yaml)), which **filters out** commits
prefixed with `docs:`, `test:`, and `chore:`. Use `feat:` and `fix:` for
changes that should appear in the release notes.

## Pull request guidelines

- Keep PRs focused; one logical change per PR when possible.
- Ensure `make fmt-check vet test` (and `make lint` if you have it) pass locally.
- Add or update tests for behavior changes; keep unit tests hermetic.
- Update `README.md` / `README.zh-CN.md` and `CHANGELOG.md` when behavior or
  documentation changes.
- Describe *what* changed and *why*, and link any related issues.
- By contributing you agree that your contributions are licensed under the
  project's [Apache-2.0](./LICENSE) license.

## 简体中文

感谢你有兴趣参与贡献！`splitdns` 是一个仅支持 macOS 的小型 Go 命令行工具，用于
管理 `/etc/resolver`，实现基于域名后缀的 Split DNS。本指南介绍如何配置开发环境、
运行各项检查，以及如何提交高质量的 Pull Request。

### 开发环境

- **macOS**（Apple Silicon 或 Intel）。本工具及其集成测试仅支持 macOS。
- **Go 1.26+**（详见 [`go.mod`](./go.mod)；模块路径为
  `github.com/soulteary/splitdns`）。
- 可选：[`golangci-lint`](https://golangci-lint.run/)，用于 `make lint`。

克隆并构建：

```bash
git clone https://github.com/soulteary/splitdns.git
cd splitdns
make build      # 生成 ./splitdns
```

### Make 目标

以下目标在 [`Makefile`](./Makefile) 中定义：

| 目标 | 作用 |
| --- | --- |
| `make fmt-check` | 使用 `gofmt` 检查格式（若有文件需要格式化则失败） |
| `make vet` | 运行 `go vet ./...` |
| `make test` | 运行单元测试（`go test ./...`） |
| `make lint` | 运行 `golangci-lint run` |
| `make build` | 构建 `./splitdns` 二进制 |
| `make integration` | 运行只读集成测试（`go test -tags integration ./...`） |

`make fmt`（不带 `-check`）会用 `gofmt -w .` 原地重写文件。

在提交 PR 前，至少运行：

```bash
make fmt-check vet test
```

### 测试

- **单元测试是自洽（hermetic）的。** 所有文件系统访问都使用临时目录，所有外部
  命令都通过可注入的假 runner 执行。它们不会触碰 `/etc/resolver`，也不会执行真实
  的系统命令，因此在任何安装了 Go 的环境中运行都是安全的。
- **集成测试是只读的，且仅支持 macOS。** 它们使用 `//go:build integration` 构建
  标签，只*观察*真实的 DNS 状态，绝不会修改 `/etc/resolver`。使用
  `make integration` 运行。

### 提交信息规范

请使用 [Conventional Commits](https://www.conventionalcommits.org/) 风格的前缀
（`feat:`、`fix:`、`docs:`、`test:`、`chore:`、`refactor:` 等）。

发布用的变更日志由 GoReleaser 生成（见 [`.goreleaser.yaml`](./.goreleaser.yaml)），
它会**过滤掉**以 `docs:`、`test:`、`chore:` 开头的提交。对于希望出现在发布说明中的
变更，请使用 `feat:` 和 `fix:`。

### Pull Request 指南

- 保持 PR 聚焦；尽量做到一个 PR 只包含一处逻辑改动。
- 确保本地通过 `make fmt-check vet test`（如已安装则也运行 `make lint`）。
- 为行为变更添加或更新测试；保持单元测试自洽。
- 当行为或文档发生变化时，更新 `README.md` / `README.zh-CN.md` 与 `CHANGELOG.md`。
- 说明*改了什么*以及*为什么*，并关联相关 issue。
- 提交贡献即表示你同意你的贡献以本项目的 [Apache-2.0](./LICENSE) 许可证授权。
